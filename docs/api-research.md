# API and performance decisions

Checked 6 September 2026. Local Node 22.19; Chrome 152.0.7977.76; Edge 152.0.4191.62. Target minimum Chromium 123 for `light-dark()` and the required extension APIs. Vanilla ES modules and packaged CSS; no runtime CDN, project server or build framework.

- [Chrome tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs): `create` has no discarded property; `discard` unloads an existing inactive tab. Creating a live URL then discarding can already cause requests. Selecting a collection therefore only changes UI. Explicit deferred resume creates a local parked page, with the URL kept durably, and activates the real URL only on selection. Never describe parked tabs as native discarded tabs. A collection stays saved after opening.
- [Service-worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle): memory is not durable. Metadata and operation records use IndexedDB transactions; listeners register synchronously; no timer-based keepalive. An interrupted close is recoverable from persisted snapshots and attempt IDs, not automatically retried against potentially recycled browser tab IDs.
- [Storage](https://developer.chrome.com/docs/extensions/reference/api/storage): credentials use local extension storage restricted to trusted contexts, never sync/export/content scripts. This is not OS-keychain encryption. Preview blobs are separate and evictable. Uninstall removes extension storage: portable backups remain essential.
- [Capture](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab): capture the active visible page only; never activate a tab to obtain an image. Respect the two-captures/second ceiling with a lower one/second limit; resize before persistence; reject captures after navigation/activation changes. Automatic capture requires a distinct opt-in host grant.
- [Optional permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions): ask from the settings/control gesture for the exact provider origin or optional bookmarks/history capability. Permission denial must leave the local core usable.
- [Network requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests): direct provider calls originate in the trusted service worker, not content scripts. No generic arbitrary-URL fetch proxy exposed to pages; input and response limits, timeouts, redirects rejected for credentials.
- [Gemini generation](https://ai.google.dev/gemini-api/docs/text-generation): direct REST generation with a user API key, structured JSON output and application-side ID validation. Output proposes local organisation; it cannot invoke arbitrary browser operations.
- [Notion page creation](https://developers.notion.com/reference/post-page) and [authorization](https://developers.notion.com/guides/get-started/authorization): use an optional user-owned internal integration token; no shipped OAuth secret or hosted broker. Portable Markdown is independent of API access. Remote outcomes need explicit pending/success/uncertain state; do not automatically repeat a possibly successful POST.
- [Obsidian URI](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI): a user-invoked note handoff, not a filesystem permission or proof of successful write. Prefer Markdown file export for larger payloads; no silent overwrite.

Verification will use task-owned browser profiles and local fixtures. Unit doubles prove operation decisions; actual extension runs must separately prove platform behaviour and persistence. Model/account-specific success must not be inferred from mocked responses.

Additional implementation evidence: Chrome's [testing guidance](https://developer.chrome.com/docs/extensions/how-to/test/end-to-end-testing) and [CDP Extensions domain](https://chromedevtools.github.io/devtools-protocol/tot/Extensions/) support loading an unpacked build and triggering its real toolbar action in a disposable test profile. [Chrome's June 2025 notice](https://developer.chrome.com/blog/extension-news-june-2025) explains removal of the legacy load flag. The Chrome 152 test uses the supported protocol route.

Notion's current [request limits](https://developers.notion.com/reference/request-limits) specify rate limits, `Retry-After` handling for 429/529, 100-element block arrays and a 500 KB request cap. The connector now stores a durable job, sends at most 100 blocks / 400 KB of block data per request, spaces successful calls and caps automatic retries at three. A lost response, malformed success or server-side failure becomes uncertain; it cannot be resent through Continue export. Known rejected batches can continue after correction. Closing the progress dialog stops subsequent batches without pretending an in-flight request was undone.

The required [Notion-Version header](https://developers.notion.com/reference/versioning) is pinned to `2026-03-11`. Page-parent exports use the documented title property and child blocks, followed by append requests to the returned page ID. Tests send the production adapter bodies over real HTTP from a Chrome extension page to local fixture endpoints. This verifies origin, headers, payload selection and journal transitions; it does not verify a user's Notion permissions or hosted model availability.

[Chrome 123's release notes](https://developer.chrome.com/blog/new-in-chrome-123) establish the CSS minimum. [Chrome's favicon API](https://developer.chrome.com/docs/extensions/how-to/ui/favicons) supplies small site icons through the extension `_favicon/` endpoint with the `favicon` permission. No remote favicon proxy or speculative page visit is used. The zero-destination-request deferred-resume check still passes after enabling it.

The general bar follows the [WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/): focus stays in the input, active-descendant tracks the highlighted result, native editing shortcuts remain intact, and IME composition is ignored by command handling. Shared action dialogs keep standalone search independent of the organiser.

The [Gemini deprecation list](https://ai.google.dev/gemini-api/docs/deprecations?hl=en), checked again on 6 September, lists no announced shutdown for the configurable `gemini-2.5-flash` default. The model is not described as newest or guaranteed available to every account. Settings allow a different exact model ID.

Actual Chrome scale fixture: 311 collections / 15,023 links; import 342 ms, full state/runtime load 122 ms, search-to-next-frame 19 ms on this machine. Only 60 collection cards and 41 search rows were mounted. These are individual local measurements, not service-level guarantees or evidence about 500 live browser renderers.
